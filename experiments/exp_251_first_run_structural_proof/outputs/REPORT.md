# 최초 실행 개선 결과

## 결론

- 최초 전체 실행 시간이 640.06초에서 136.94초로 줄어듦
- 503.12초 단축, 78.6% 개선임
- 가장 무거운 데이터 모델 단계는 628.05초에서 122.97초로 줄어듦
- 실제 자료, 전체 309종목, 8년 7개월, 일별 2,095일, 위험 상황 64개를 그대로 사용함
- 팩터 419,576행의 파일이 기존과 바이트 단위로 같음
- 계좌, 체결, 종목별 비중의 경제적 내용도 모두 같음
- 최대 메모리는 562MB에서 1.91GB로 늘어 정한 기준을 통과하지 못함
- 따라서 자동 적용이 아니라 사용자가 선택하는 기능으로 게시함

## 작동 방식

```text
실제 원천 자료
  -> 자료 등록과 검사
  -> 매일 필요한 과거 자료 읽기
  -> 여러 팩터 결합
  -> 64개 위험 상황의 공분산 만들기
  -> 구조만으로 안전 여부 증명
       -> 증명 성공: 바로 계산
       -> 증명 불충분: 기존 안전 계산
  -> 일별 팩터 자료 저장
  -> 매주 상위 30개 매수·하위 30개 매도
  -> 계좌·체결·비중 저장
  -> 조회와 내보내기
```

- 시간 기준은 통과하고 메모리 기준은 실패함

## 확인된 병목

- 기존 첫 실행은 위험 행렬마다 고유값 전체를 검사함
- 실제 전체 실행에서 이런 계산을 134,080번 수행함
- 자료 준비나 매매보다 데이터 모델의 반복 안전 검사가 훨씬 큰 비중임

## 개선안의 가설·방법·결과

- 가설: 행렬을 만드는 방법을 알면 고유값을 직접 보지 않고 안전함을 증명할 수 있음
- 방법: 가중 수익률, 대각선 보정, 작은 양수 추가를 새 도구가 직접 담당함
- 결과: 134,080번 중 133,888번을 첫 실행에서 바로 계산함
- 증명 성공률 99.86%임
- 나머지 192번은 기존 안전 계산으로 자동 복귀함
- 안전 기준이 실제 발동한 경우는 0번임
- 앞선 증분 계산은 전체 약 2초만 줄고 마지막 자리 수치가 달라 채택하지 않음
- 이번 병목은 자료 조회가 아니므로 데이터베이스·SQL·C 언어 변경은 먼저 적용하지 않음

## 기존과 신규 구조

| 항목 | 기존 첫 실행 | 신규 첫 실행 |
|---|---|---|
| 안전 확인 | 행렬마다 고유값 검사 | 만드는 구조로 먼저 증명 |
| 증명 실패 | 해당 없음 | 기존 계산으로 자동 복귀 |
| 반복 실행 | 인증 파일로 단축 가능 | 구조 증명 또는 인증 파일 선택 가능 |
| 결과 | 기준 | 동일 |
| 전체 시간 | 640.06초 | 136.94초 |
| 최대 메모리 | 562MB | 1.91GB |

## 결과 동일성

- 팩터 파일 해시가 기존과 같음: `e50702562ba46f73296f7c14da38f205ae9bb5c10ea6259d42d56770e688f9d0`임
- 계좌 129,456행의 경제적 내용이 같음
- 체결 32,643행의 경제적 내용이 같음
- 비중 26,760행의 경제적 내용이 같음
- 실행 식별자는 코드 지문이 달라 서로 다름. 투자 결과 차이는 아님

## 최종 코드와 사용 방법

- 공개 기능 `ShrunkCovarianceSolver`를 추가함
- 가중 관측값, 축소 비율, 작은 양수를 받아 행렬을 직접 만듦
- 일반 행렬을 받아 근거 없는 증명을 허용하지 않음
- 한 계산 안에서는 같은 도구를 계속 재사용해야 함
- 구조가 다른 행렬은 기존 `SpectralFloorSolver`를 사용함

## 현실성과 남은 한계

- 실제 DW 자료와 실제 공개 명령 경로를 사용함
- 단순 합성 자료나 짧은 시험을 최종 근거로 쓰지 않음
- 기존 실행이 10분을 넘는 조건을 그대로 사용함
- 한 컴퓨터와 한 수치 연산 스레드에서 측정함
- 최대 메모리 변동이 크며 정한 10% 기준을 실패함
- 메모리 원인을 별도 추적하기 전 자동 엔진 적용은 하지 않아야 함
- 지원되는 공분산 구조에만 효과가 큼. 모든 전략이 같은 폭으로 빨라지는 것은 아님
