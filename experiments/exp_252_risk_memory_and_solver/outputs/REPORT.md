# 위험 계산 2차 개선 결과

## 결론

- 정식 제품 코드의 전체 실행이 136.94초에서 98.88초로 줄어듦
- 최초 기준 640.06초와 비교하면 84.6% 단축됨
- 데이터 모델은 122.97초에서 85.85초로 줄어듦
- 안전 증명 뒤 일반 풀이 대신 양의 정부호 전용 풀이를 사용한 결과임
- 전체 134,080회 중 133,888회는 빠르게 계산하고 192회는 기존 안전식으로 돌아감
- 팩터 파일과 계좌·체결·비중 결과가 모두 같음
- 세 번 교차 측정한 후보 중앙값은 전체 91.27초, 데이터 모델 78.45초임
- RSS는 약 2GB로 보였지만 운영체제의 실제 물리 메모리 최고값은 302.5MB임

## 기존 흐름과 병목

```text
공분산 생성 -> 구조 안전 증명 -> 일반 행렬 풀이 -> 점수 생성
```

- 고유값 검사를 제거한 뒤 일반 행렬 풀이가 남은 데이터 모델 시간의 약 80%를 차지함
- 현재 환경의 단순 직접 풀이 3회 중앙값은 111.03초임
- 구조 증명 자체는 3개월 시험에서 약 5% 비용을 추가함
- 데이터 읽기와 일반 팩터 계산은 합쳐 약 9초로 후순위임

## 개선안과 효과

```text
공분산 생성
  -> 구조 안전 증명
       -> 성공: Cholesky 전용 풀이
       -> 불충분 또는 실패: 기존 고유값 분해와 안전 보정
  -> 점수 생성
```

- NumPy의 Cholesky와 일반 풀이 두 번 조합은 일반 풀이보다 2.3배 느려 기각함
- SciPy의 한 번의 Cholesky 분해·풀이는 309종목 시험에서 약 48% 빨랐음
- 안전 검사를 생략한 속도 상한은 전체 92.15초였음
- 안전 증명을 붙인 최종 후보 3회는 89.77초, 92.53초, 91.27초임
- 같은 환경의 단순 직접 풀이 3회는 125.47초, 116.06초, 123.75초임
- 최종 제품 코드 재실행은 98.88초임

## 메모리 판정

- 단순 직접 풀이와 최종 후보 모두 `ps`의 RSS가 약 2.0~2.4GB로 측정됨
- 따라서 새 풀이만의 메모리 증가가 아님
- `vmmap`이 기록한 실제 물리 메모리 최고값은 302.5MB임
- 종료 시 실제 물리 메모리는 247.7MB임
- RSS에는 공유 라이브러리, 가속기 매핑, 비어 있는 예약 영역이 섞여 있었음
- 실제 물리 메모리는 고정한 700MB 기준 안임
- 이후 macOS 측정에서는 RSS와 physical footprint를 함께 기록해야 함

## 결과 동일성

- 팩터 419,576행이 바이트 단위로 같음
- 팩터 SHA-256은 `e50702562ba46f73296f7c14da38f205ae9bb5c10ea6259d42d56770e688f9d0`임
- 주간 목표 비중 26,760행이 같음
- 계좌 129,456행의 경제적 내용이 같음
- 체결 32,643행의 경제적 내용이 같음
- 실제 안전 보정이 발동한 경우는 0회임

## 최종 변경

- `ShrunkCovarianceSolver`의 증명 성공 경로에 Cholesky 전용 풀이를 적용함
- 증명에 쓰는 안전 여유도 행렬 전체를 다시 만들지 않는 상한으로 바꿈
- SciPy 1.18 이상을 정식 실행 의존성으로 추가함
- 기존 `SpectralFloorSolver`와 실패 시 안전 공식은 유지함

## 남은 한계

- 지원되는 대각선 축소 공분산 구조에서만 큰 효과가 남
- Cholesky는 마지막 자리 수치가 다를 수 있으나 실제 최종 팩터 파일은 같았음
- 일반 팩터와 읽기 최적화의 남은 최대 폭은 약 9초임
- 공통 행렬 재사용과 증분 공분산은 앞선 시험에서 수치 차이와 작은 효과 때문에 계속 기각함
