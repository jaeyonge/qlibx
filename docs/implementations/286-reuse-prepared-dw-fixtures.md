# 286 — 바뀌지 않은 DW 시험자료는 다시 만들지 않음

## 결론

- 같은 DW 원본과 같은 시험 조건이면 한 번 준비한 Parquet 파일을 재사용함
- 원본 파일이나 기간·종목 수가 바뀌면 자동으로 다시 만듦
- 실제 DW 예제의 반복 실행이 약 8초에서 약 1초로 줄었음

## 왜 바꿨는가

- 실제 DW 예제는 720MB 가격 CSV와 101MB 구성종목 CSV를 실행할 때마다 다시 검색했음
- 프로파일 측정에서 이 준비 작업이 전체 시간의 88.6%였음
- 두 예제는 같은 조건의 시험자료를 쓰면서도 각각 다시 만들었음

## 작동 방식

- 요청한 기간·종목 수와 두 원본 파일의 위치·크기·수정 시각을 하나의 식별값으로 만듦
- 같은 식별값으로 준비된 파일이 있으면 결과 폴더에 그대로 복사함
- 어느 하나라도 바뀌면 큰 CSV를 다시 읽고 새 식별값 아래에 보관함
- 캐시는 속도 보조 수단일 뿐이며, 실제 실행 기록이나 투자 결과는 캐시하지 않음

## 측정 결과

| 조건 | 기존 | 개선 | 효과 |
|---|---:|---:|---:|
| DW 자료 준비만, 최초 | 7.06초 | 6.94초 | 느려지지 않음 |
| DW 자료 준비만, 반복 | 7.06초 | 0.002초 | 약 4,009배 |
| 실제 DW 롱숏 전체 실행 | 7.758초 | 0.99초 | 약 7.8배 |
| KRX 체결 비교 전체 실행 | 8.361초 | 1.04초 | 약 8.0배 |

- 준비된 세 Parquet와 설명 파일의 바이트 해시가 최초·반복 실행에서 모두 같음
- 실제 두 예제의 자체 결과 검증도 모두 통과함
- 최초 실행은 캐시 효과를 주장하지 않음

## 한계

- 파일 내용이 달라졌는데 크기와 수정 시각을 인위적으로 똑같이 되돌린 경우는 알아채지 못함
- 일반적인 파일 교체·갱신은 크기 또는 나노초 수정 시각이 달라져 다시 준비함
