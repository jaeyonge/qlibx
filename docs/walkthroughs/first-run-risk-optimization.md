# 온보딩부터 결과 분석까지 전체 실행 성능 개선

## 결론

- 최초 전체 실행 시간이 640.06초에서 98.88초로 줄어듦
- 541.18초 단축, 84.6% 개선임
- 1차 개선에서 136.94초까지 줄인 뒤, 2차 개선에서 98.88초까지 추가로 줄임
- 데이터 모델 생성은 628.05초에서 85.85초로 줄어듦
- 실제 자료, 전체 309종목, 2018년 1월부터 2026년 7월까지의 기간을 사용함
- 매일 64가지 위험 상황을 계산하고 매주 상위 30종목 매수, 하위 30종목 매도함
- 팩터 419,576행과 투자 결과가 기존과 같음
- macOS RSS는 공유 영역 때문에 약 2GB로 보였으나 실제 물리 메모리 최고값은 302.5MB임
- 지원되는 위험 계산에서 사용자가 선택하는 기능으로 제공함
- 수익률만 조회하는 후처리는 2.73초에서 0.24초로 줄어 약 11.5배 빨라짐
- 같은 DW 구간을 반복 준비하는 전체 예제는 약 8초에서 약 1초로 줄어 약 8배 빨라짐
- 최초 계산, 반복 자료 준비, 실행 후 성과 조회라는 서로 다른 병목을 각각 개선함

## 기존 코드는 어떻게 작동했나요?

- 과거 주가, 거래량, 거래대금, 재무지표, 예상 실적, 지수 편입 정보를 불러옴
- 모멘텀, 가치, 퀄리티, 이익 변화, 유동성, 규모 등의 요인을 계산함
- 여러 요인을 합쳐 종목별 기본 점수를 만듦
- 과거 수익률을 이용해 종목들이 서로 얼마나 같이 움직이는지 계산함
- 여러 시장 상황을 가정해 위험 계산을 반복함
- 위험을 반영한 종목별 최종 점수를 만듦
- 매주 점수가 높은 30종목을 매수하고 낮은 30종목을 매도함
- 과거 전체 기간에 이 과정을 반복해 전략 성과를 평가함

이번 시험의 위험 계산 규모는 다음과 같음.

- 계산 일수: 2,095일임
- 대상 종목: 실제 KOSPI 200 과거 구성 종목 309개임
- 하루 위험 상황: 64개임
- 전체 위험 계산: 134,080회임

기존 코드는 위험 계산표가 안전한지 확인하기 위해 매번 표의 전체 구조를 검사함. 너무
작거나 불안정한 값이 있으면 작은 값을 일정 수준까지 올린 뒤 계산함. 계산 오류를 막는 중요한
안전장치이지만, 같은 종류의 정밀 검사를 수십만 번 반복함.

## 기존 코드의 병목은 무엇이었나요?

- 가장 큰 병목은 데이터 조회나 매매 주문 생성이 아니었음
- 위험 계산표의 전체 고유값을 매번 검사하는 과정이 가장 느렸음
- 이런 검사를 실제 전체 실행에서 134,080번 수행함
- 최초 버전의 전체 실행은 약 640초였음
- 이 중 데이터 모델 생성에 약 628초가 사용됨
- 실제 점수 계산보다 그 계산이 안전한지 확인하는 과정에 많은 시간이 사용됨
- 1차 개선 뒤에는 안전 증명 다음에 쓰는 일반적인 행렬 풀이가 가장 큰 남은 병목이었음

쉽게 말하면 자동차를 운전하기 전에 엔진 전체를 매번 분해해 확인하는 방식과 비슷함. 안전하지만
동일한 형태의 검사를 반복하기 때문에 오래 걸림.

## 무엇을 개선했으며 효과는 어땠나요?

### 개선 방법

개선은 두 단계로 진행함.

- 1차 개선: 위험 계산표가 어떻게 만들어졌는지를 이용해 전체를 살펴보지 않고도 먼저 안전성을
  증명함
- 2차 개선: 안전성이 증명된 표는 그 성질에 맞는 더 빠른 전용 계산법으로 풂

새로운 방식도 안전 검사를 없애지 않음. 전용 계산에 실패하거나 안전성을 충분히 증명하지 못하면
기존의 정밀 검사와 안전 계산으로 자동 복귀함.

위험 계산표는 다음 요소를 합쳐 만듦.

- 과거 수익률로 계산한 종목 간 움직임임
- 개별 종목의 위험값을 안정시키는 보정임
- 모든 종목에 더하는 작은 안전값임

새로운 실행 흐름은 다음과 같음.

```text
가중치를 적용한 과거 수익률
  -> 위험 계산표를 직접 만듦
  -> 표를 만든 구조로 안전성을 증명함
       -> 증명 성공: 정밀 검사를 생략하고 전용 계산법으로 풂
       -> 증명 불충분: 기존 안전 계산으로 자동 복귀함
  -> 위험을 반영한 종목 점수를 만듦
```

- 안전 기준을 낮추지 않음
- 확실하게 증명되는 경우에만 정밀 검사를 생략함
- 확실하지 않은 경우에는 기존 계산으로 돌아감
- 사용자가 임의로 만든 표를 안전하다고 선언할 수 없게 함
- 새 기능이 과거 수익률부터 위험 계산표를 직접 만들어야 빠른 증명을 사용할 수 있음

### 적용 범위와 주의점

효과가 큰 경우는 다음과 같음.

- 종목 간 위험 관계를 반복해서 계산하는 전략임
- 많은 종목을 대상으로 공분산을 계산하는 전략임
- 여러 위험 상황을 반복 계산하는 전략임
- 기존 실행시간 대부분이 위험 계산에 사용되는 전략임
- 대각선 보정과 작은 안전값을 더하는 위험 모델임

효과가 제한적인 경우는 다음과 같음.

- 위험 행렬을 사용하지 않는 전략임
- 종목 수가 매우 적은 전략임
- 데이터 조회나 외부 통신이 주된 병목인 전략임
- 이번에 지원한 방식과 다른 위험 모델임

단순 RSS는 약 2GB로 보였지만 같은 환경의 기존 풀이도 같았음. 운영체제 메모리 지도로 다시
확인한 실제 물리 메모리 최고값은 302.5MB였음. 공유 라이브러리와 예약 공간이 RSS에 섞인
측정 착시였으며 실제 메모리는 700MB 기준 안임.

## 최종 코드는 어떻게 사용하나요?

### 브랜치

- 저장소: [jaeyonge/qlibx](https://github.com/jaeyonge/qlibx)
- 브랜치: [codex/v016-certified-risk-onboarding](https://github.com/jaeyonge/qlibx/tree/codex/v016-certified-risk-onboarding)
- 기준 버전: 원본 저장소의 `v0.16.0` 개발 브랜치 구조임

### 새 기능

`ShrunkCovarianceSolver`를 공개 기능으로 추가함.

- 가중치를 적용한 과거 수익률을 받음
- 종목 간 위험 관계를 계산함
- 종목별 보정값과 안전값을 더함
- 계산표를 만든 구조로 안전성을 증명함
- 증명에 성공하면 바로 위험 조정 점수를 계산함
- 증명이 부족하면 기존 안전 계산을 사용함
- 안전성이 증명되면 양의 정부호 행렬에 맞는 Cholesky 전용 계산법을 사용함
- 전용 계산 자체가 실패해도 기존 안전 계산으로 자동 복귀함
- 빠른 계산과 기존 계산이 각각 몇 번 사용됐는지 기록함

기존 `SpectralFloorSolver`도 그대로 유지함. 일반적인 위험 행렬과 반복 실행 인증에는 기존 기능을
계속 사용할 수 있음.

새 전용 계산에 필요한 SciPy는 vqapr의 정식 의존 프로그램으로 등록함. 사용자는 평소처럼 패키지를
설치하면 되며 SciPy를 따로 설치할 필요가 없음.

### 사용 예시

```python
from vqapr import public as vq

solver = vq.ShrunkCovarianceSolver(
    shrinkage=0.05,
    ridge=1e-6,
)

result = solver.solve(
    weighted_returns,
    signal,
)

adjusted_signal = result.solution
raw_variance = result.diagonal
evidence = solver.stats.as_record()
```

- `weighted_returns`: 가중치를 적용한 과거 수익률임
- `signal`: 여러 요인을 결합한 기본 종목 점수임
- `shrinkage`: 개별 종목 위험 쪽으로 보정하는 정도임
- `ridge`: 계산이 깨지지 않도록 더하는 작은 안전값임
- `adjusted_signal`: 위험을 반영한 최종 종목 점수임
- `raw_variance`: 각 종목의 원래 위험 크기임
- `proved`: 빠른 안전 증명에 성공한 횟수임
- `audited`: 기존 안전 계산으로 돌아간 횟수임

위험 상황을 여러 번 계산할 때는 같은 설정의 계산 도구를 반복해서 사용해야 함. 서로 다른
보정 비율을 사용한다면 비율별로 계산 도구를 하나씩 만들어 재사용함.

### 실행 후 수익률만 빠르게 읽기

팩터 포트폴리오를 합치거나 여러 전략의 수익률만 비교할 때는 전체 보고서 대신 성과 전용 경로를
사용함.

```python
from vqapr.public import strategy_performance

performance = strategy_performance(".vqapr", "my-run")
daily_returns = performance.returns
```

- 계좌 합계 행과 필요한 열만 읽음
- 종목별 손익, 체결, 목표 비중 분석은 만들지 않음
- 수익률·낙폭·샤프지수 계산법은 기존 전체 보고서와 같음
- 종목별 분석까지 필요하면 기존 `strategy_report`를 사용함

### 같은 DW 시험자료 반복 사용

- 실제 DW Showcase의 실행 명령은 바뀌지 않음
- 원본 파일, 기간, 종목 수가 같으면 한 번 준비한 Parquet를 다시 사용함
- 원본이나 조건이 바뀌면 자동으로 다시 준비함
- 투자 결과는 캐시하지 않으므로 전략 실행과 기록은 매번 독립적으로 남음
